# DROP_Lottery

イベント向けの簡易抽選システムです。画面は GitHub Pages、API は Google Apps Script（GAS）、データは Google スプレッドシートに置きます。当落判定・在庫・引換の判定はすべて GAS で行い、画面は表示と API 呼び出しだけを担います。

## 流れ

```
LP（index.html） → アンケート（survey.html） → 抽選（lottery.html） → 結果・引換
```

1. **LP**：スタンプラリーから URL パラメータでユーザーIDとスタンプ数（シート上の「ポイント」）を受け取り、スタンプ数に合うボタンを1つだけ有効にする。
   `https://obayashi-smartcity.github.io/DROP_Lottery/?account_id=<ユーザーID>&point=<スタンプ数>`（パラメータ名は `assets/config.js` で変更可）。手入力欄はなく、ユーザーIDは画面に表示しない。
   ユーザーIDは UUID（大文字・小文字どちらでも受け付け、小文字にそろえて使う）。スタンプ数は 0 以上の整数で、Config の `MAX_POINTS` 以下。
   パラメータがない・形式が不正なときは「スタンプラリーのページから開いてください」を表示する。読み取ったパラメータはアドレスバーから消し、画面間の状態（sessionStorage）に保持する（再読み込みしても続きから表示できる）。
2. **アンケート**：全ボタン共通の6問（全問必須。設問は `assets/survey-config.js`）。画面下の「抽選する」を押すと、回答をアンケートGASが `DROP_Lottery_Survey` に記録し、そのまま抽選に進む。「その他」を選ぶと自由記述の入力欄が出て、入力が必須になる。「特に当てはまるものはない」はほかの選択肢と同時に選べない。
3. **抽選**：抽選ページを開くと自動で抽選する（抽選ページに「抽選する」ボタンはない）。選んだボタンの当選確率で当落を決め、当たりなら通常の景品の残りから割り当てる（残り数に比例した確率）。はずれ、または通常の景品が残っていなければ、はずれ景品（Prizes の区分が「はずれ」の行。オリジナルポストカード）を割り当てる。はずれ景品も残っていなければ景品なしのはずれ。
4. **結果・引換**：当たりなら「当選おめでとうございます！」（カードの見出しは「抽選特典」）、はずれ景品なら「残念！はずれ」（「参加賞」）と、引換パスワードの入力欄を表示する（景品名は出さない）。引換所（国立国際美術館B1階インフォメーション）で当選者が画面を見せ、スタッフが示したパスワードを入力して「受け取る」を押すと「引換済み」になる（カードの見出しは「抽選特典（受け取り済）」など）。スタッフはその画面を見て景品を渡す。

- 抽選はユーザーIDごとに1回。抽選済みのIDで LP に来ると「このユーザーIDの抽選は完了しています」と結果を表示する（ページを閉じても、スタンプラリーのリンクから入り直せば結果画面が出る）。
- 画面の見出しはすべて「特典抽選ページ」（LP・抽選画面は Config の `EVENT_NAME` を表示する）。画面の右上に小さく画面のバージョン（`assets/config.js` の `APP_VERSION`。GAS のバージョンとは別。下の「画面のバージョン」）を出す。
- LP を通らずにアンケート・抽選ページを直接開いた場合は LP に戻す。

初期設定のボタン（`Tiers` シートで変更可）：

| スタンプ数 | 有効になるボタン |
| --- | --- |
| 4以下 | なし（抽選不可） |
| 5〜9 | 当選確率１倍ボタン |
| 10〜24 | 当選確率２倍ボタン |
| 25〜49 | 当選確率３倍ボタン |
| 50〜 | 当選確率４倍ボタン |

| --- | --- | --- |

| スプレッドシート | `DROP_Lottery_Survey` | アンケート回答（Responses シート） |

## 設定を変える場所

| 変えたいもの | 場所 |
| --- | --- |
| ボタンの数・名前・ポイントの範囲・当選確率 | `DROP_Lottery_DB` の **Tiers** シート（1行＝1ボタン。上から順に表示。最大ポイントが空欄なら上限なし。確率は %）。**tierId は英字で始める**（下の「ID のルール」） |
| 景品と数 | `DROP_Lottery_DB` の **Prizes** シート（行を増やしたら抽選GASの `setupSheets` を実行して集計式を入れる）。H列「区分」に `はずれ` と入れた景品は、通常の景品に当たらなかった人に渡す。**prizeId は英字で始める**（下の「ID のルール」） |
| 画面の見出し（イベント名）・受付期間・引換期限・受付停止 | `DROP_Lottery_DB` の **Config** シート（見出しは `EVENT_NAME`。「特典抽選ページ」にする。アンケート画面の見出しは `survey.html` に直書き） |
| スタンプ数の上限 | `DROP_Lottery_DB` の **Config** シートの `MAX_POINTS`（0 以上の整数。行がない・空欄・不正な値なら 10,000,000。これを超えるスタンプ数で来たら LP は「スタンプラリーのページから開いてください」を表示し、GAS も抽選を受け付けない）。10,000,000 より大きくする場合は `gas/survey/Code.gs` の `MAX_POINTS` も上げる |
| 引換パスワードの失敗回数の上限・ロック時間 | `DROP_Lottery_DB` の **Config** シートの `REDEEM_MAX_FAIL`（回）・`REDEEM_LOCK_MIN`（分、最大 360）。行がない・空欄・正の整数でないときは 10 回・5 分 |
| 引換パスワード | `DROP_Lottery_DB` の **Config** シートの `REDEEM_PASSWORD`（初期値 0884。先頭の0が消えないよう文字列で入れる） |
| アンケートの設問 | `assets/survey-config.js`（新しい設問IDは Responses シートに列が自動で追加される。`otherOption`（選ぶと自由記述の入力欄を出す選択肢。内容は `<設問ID>_other` の列）・`exclusiveOptions`（ほかと同時に選べない選択肢）も指定できる） |
| 結果画面の文言（見出し・「抽選特典」「参加賞」・案内文） | `lottery.html` と `assets/lottery.js` の `TEXT` に直書き |
| 画面のバージョン（右上に表示） | `assets/config.js` の `APP_VERSION` と、3つの HTML の `?v=`（**必ず同時に変える**。下の「画面のバージョン」） |
| 「スタンプラリーに戻る」ボタンの戻り先（LP・結果画面に表示） | `assets/config.js` の `STAMP_RALLY_URL`（空にするとボタンを出さない） |
| 遷移元から受け取る URL パラメータ名 | `assets/config.js` の `PARAM_USER_ID`（`account_id`）・`PARAM_POINTS`（`point`） |
| 混雑・通信エラー時の自動再試行 | `assets/config.js` の `RETRY_TOTAL_MS`（合計の打ち切り、既定 30 秒）・`RETRY_BASE_MS`・`RETRY_MAX_DELAY_MS` |
| GAS の URL | `assets/config.js` の `GAS_URL`（抽選）・`SURVEY_GAS_URL`（アンケート） |

スプレッドシートの変更は GAS の再デプロイなしで反映されます。ただし **Config・Tiers・Prizes は30秒キャッシュするので、反映まで最大30秒かかります**（受付停止 `ACCEPTING=FALSE` や引換パスワードの変更を含む）。すぐ反映したいときは、抽選GAS のエディタで関数 `clearSettingsCache` を実行してください。

### ID のルール

- **Tiers の tierId と Prizes の prizeId は英字で始めます**（例: `B1`、`P01`）。`1`・`01`・`1B` のように英字で始まらない ID があると、抽選GAS は `NOT_CONFIGURED`（「Tiers シートのボタンID（tierId）「1」が英字で始まっていません…」のように、シート名と ID を示すエラー）を返して止まります。
  - Tiers の誤り: 新しい参加者の LP（`info`）・新規の抽選が止まる。抽選済みの人は、LP から結果画面へ進める（LP は抽選済みなら `info` の失敗に関係なく結果画面へ進む）ので、結果の表示と引換は止まらない。
  - Prizes の誤り: 新規の抽選だけが止まる。LP・当選者の結果画面・引換は止まらない（期間中に景品を足して ID を誤っても、当選済みの人には影響しない）。
  - このエラーは Logs シートに `NOT_CONFIGURED` として残る（v4.0-07、D-42）。
  - 直したら `clearSettingsCache` を実行する（しなければ最大30秒で反映）。
- 理由: 抽選の記録（Users・Winners）は `appendRow` で追加するので、値の型はシートが推測します。数字だけの ID は数値に化け、照合や在庫の数え方が狂います（D-30）。
- 抽選が始まった後は ID を変えないでください（記録済みの ID と合わなくなります）。期間中に ID を書き換えることは想定していません。上のチェックは、通常の使い方では動かない保護の仕組みです。

## 緊急停止

1. `DROP_Lottery_DB` の **Config** シートで `ACCEPTING` を `FALSE` にする。
2. 抽選GAS のエディタで関数 **`clearSettingsCache`** を実行する（しないと最大30秒は抽選を受け付ける）。
3. 新しく LP を開いた人に受付外の表示が出ることを確かめる。

- 止まるのは **新規の抽選だけ** です。**抽選済みの人の結果表示と引換（パスワード入力）は止まりません。**
- 引換も止めたいときは、Config の `REDEEM_DEADLINE` を過去の日時にする（未引換は期限切れの表示になる）か、`REDEEM_PASSWORD` を変えて、同じく `clearSettingsCache` を実行します。
- 再開するときは `ACCEPTING` を `TRUE` に戻し、`clearSettingsCache` を実行します。

## 監視

| 見るもの | 場所 | 見方 |
| --- | --- | --- |
| 混雑の手前 | `DROP_Lottery_DB` の **Logs** シートの成功した `draw` 行の詳細（`wait=…ms hold=…ms`）の `wait` | ロックを待った時間。**5〜10秒の行が増えたら混雑の手前**（10秒を超えると BUSY） |
| BUSY（混雑で受け付けられなかった要求） | **Logs** シートの結果が `BUSY` の行 | 同時に大量に来ると欠ける（実際の件数の約4割しか残らない）ので、**最低限の件数** として見る |
| ロックの保持時間 | **Logs** シートの `draw` 行の `hold` | 1件の抽選がロックを持っていた時間。負荷試験では平均 約1.0秒（最大 約2.1秒） |
| 動いているバージョン | 抽選GAS のエディタの **「実行数」** 画面の「導入」列 | デプロイしたバージョン番号になっているかの確認に使う。BUSY の実行ログ（`console.warn`）は、匿名アクセスの実行なので標準の設定では見られない（行が開けず、「Cloud のログ」も押せない。Cloud プロジェクトへの紐づけが必要） |
| 在庫 | `DROP_Lottery_DB` の **Prizes** シートの集計列 | 当選数・引換数・手元残数・当選可能残（数式で自動計算）。ボタン別の抽選数などは Users シートを見る |
| 不正なアクセス・設定のエラー（調査用） | **Logs** シートの結果が `BAD_REQUEST`・`UNKNOWN_ACTION`・`BAD_USER`・`NOT_CONFIGURED` の行（v4.0-07、D-42） | `NOT_CONFIGURED` は ID の誤りなど設定のエラー。ほかの3つは正規の画面からは出ないので、画面を通さない呼び出しの手がかりになる（受け取った値の先頭を詳細に残す）。同時に大量に来ると欠ける |

- 同時に約10件までは全員成功し、それを超えた分は画面の自動再試行（合計30秒程度）で吸収する前提で運用しています（D-31）。
- 実績で BUSY が続く（自動再試行でも吸収しきれない）ようなら、`gas/lottery/Code.gs` の `LOCK_WAIT_MS`（ロックの待ち時間、10秒）を15秒程度に延ばすことを検討します。その場合は画面の1回の要求の打ち切り（`assets/config.js` の `REQUEST_TIMEOUT_MS`、20秒）と合計の打ち切り（`RETRY_TOTAL_MS`、30秒）も合わせて見直します。

## スプレッドシートの中身

### DROP_Lottery_DB

| シート | 内容 |
| --- | --- |
| Config | イベント設定（キーと値） |
| Prizes | 景品。当選数・引換数・手元残数・当選可能残は式で自動計算 |
| Tiers | ボタン（tierId・ボタン名・最小/最大ポイント・当選確率） |
| Users | ユーザーIDごとの抽選結果（1人1行）。ポイント・ボタン・deviceId も記録 |
| Winners | 当選者（ticketId・景品・引換状態・引換日時・userId） |
| Logs | 操作ログ（抽選・引換・エラーなど。v4.0-07 から `BAD_REQUEST`・`UNKNOWN_ACTION`・`BAD_USER`・`NOT_CONFIGURED` も） |

### DROP_Lottery_Survey

Responses シートに1回答1行。受信日時・userId・ポイント・tierId・ボタン名・deviceId・画面から渡されたパラメータ（JSON）・回答（JSON）と、設問IDごとの列が並びます。複数選択の回答は「, 」区切りで1つのセルに入ります。「その他」の内容は `<設問ID>_other` の列に入ります（選んでいなければ空欄）。設問を入れ替えたときは、リリース前に Responses シートを見出しごと消します（古い設問の列が残らないように）。

## 画面のバージョン

画面（Pages）のバージョンは **`v1.0.0` から始め、GAS のバージョン（`v4.0-07` など）とは別に管理** します（D-52）。画面の右上に小さく表示します。

- **上げるとき**: 参加者の画面のファイル（`index.html`・`survey.html`・`lottery.html`、`assets/` の CSS・JS。`config.js`・`survey-config.js` を含む）を変えて Pages に反映するとき。GAS だけ・ドキュメントだけの変更では上げない。
- **番号の付け方**: 文言・見た目の修正は3桁目（`v1.0.1`）、画面の動きが変わる変更（設問の入れ替え・機能の追加など）は2桁目（`v1.1.0`）、作り直しなど大きな変更は1桁目（`v2.0.0`）。
- **キャッシュ対策**: HTML は CSS・JS を `?v=<画面のバージョン>` 付きで読み込みます。Pages に反映した直後に、スマホに古い HTML が残っていて新しい JS と混ざると、画面が壊れることがあるためです（v4.0-07 の確認で実際に起きた）。`?v=` を変えると、新しい HTML は必ず新しい CSS・JS を読み込みます。
- 古い HTML と新しい JS が混ざったことに画面が気づいたとき（HTML の `?v=` と `config.js` の `APP_VERSION` が違うとき）は、「画面が新しくなりました。ページを再読み込みしてください。」と再読み込みボタンを出します。画面の部品が見つからないなどのエラーも、技術的な文言ではなく「画面を表示できませんでした。ページを再読み込みしてください。」と出します。

上げる手順（**`APP_VERSION` と HTML の `?v=` は必ず同時に変える**）:

1. `assets/config.js` の `APP_VERSION` を新しい値にする（例: `'v1.0.0'` → `'v1.0.1'`）。
2. `index.html`・`survey.html`・`lottery.html` の CSS・JS の `?v=` を **すべて同じ値** にする（3ファイルで計13か所。一括置換でよい: `?v=v1.0.0` → `?v=v1.0.1`）。
3. 変え忘れがないか確かめる: `node tools/check-version.mjs`（`OK: … 13 か所の ?v= がすべて同じです` と出ればよい。違えば NG と、合っていない箇所が出る）。
4. コミットして Pages に反映する（画面のバージョンとコミット ID をコミットの説明に書く）。
5. 反映後、スマホで LP を開き、右上のバージョン番号が新しい値になっていること、「画面が新しくなりました。ページを再読み込みしてください。」が出ないことを確かめる（出た場合は、古い HTML がキャッシュに残っている。再読み込みで消えなければ、1〜2 の変え忘れを疑う）。

## デプロイ

画面は GitHub Pages、API は GAS のウェブアプリです。

### GAS をウェブアプリとして公開する

1. デプロイ > 新しいデプロイ > 種類「ウェブアプリ」。
2. 次のユーザーとして実行：自分 / アクセスできるユーザー：全員。
3. 表示された URL（`…/exec`）を `assets/config.js` に貼る。

コードを直したときは、`gas/` の変更をコミットしてから Apps Script エディタに貼り付け、「デプロイを管理」で既存のデプロイを編集してバージョンを「新バージョン」にします（URL は変わりません）。バージョンの説明にはコミット ID を書きます。保存しただけでは公開中の API には反映されません。

現在 `assets/config.js` に入っているのは、どちらも説明が「test: …」のデプロイです。抽選GASの旧デプロイ（説明「無題」）は旧画面用で、今の画面とは互換性がありません。

### 初回のセットアップ（新しい環境で作り直す場合）

抽選GAS（DROP_Lottery）：

1. 関数 `setupSheets` を実行する（初回は権限の承認が必要）。Users・Winners の ID の列を文字列書式にする（手で入力・修正する行のためで、抽選で追加される行には効かない）。Tiers・Users シート、Config の `REDEEM_PASSWORD`・`MAX_POINTS`・`REDEEM_MAX_FAIL`・`REDEEM_LOCK_MIN`（行がなければ追加）、Prizes の集計式ができる（何度実行してもデータは消えない）。
2. ウェブアプリとしてデプロイし、URL を `GAS_URL` に貼る。

v4.0-07 から `setupSecrets` はありません（スタッフ PIN と署名鍵を使わなくなったため。D-43）。スクリプト プロパティに `STAFF_PIN`・`HMAC_SECRET` が残っていても害はありません（消してよい）。

アンケートGAS（DROP_Lottery_Survey_API）：

1. 関数 `setupSheet` を実行する（初回は権限の承認が必要）。Responses シートができる。
2. ウェブアプリとしてデプロイし、URL を `SURVEY_GAS_URL` に貼る。

## 不正防止の仕組み

| 不正 | 対策 |
| --- | --- |
| 同じユーザーIDで何度も抽選 | Users シートでユーザーIDごとに1回。抽選済みなら前回の結果を返す |
| スタンプ数と違うボタンで抽選 | GAS が Tiers を見てスタンプ数とボタンの組み合わせを検証する |
| 同じ当選で何度も引換 | 引換は GAS のロック内で「未引換 → 引換済み」を1回だけ行う |
| 引換パスワードの総当たり | ユーザーIDごとに Config の `REDEEM_MAX_FAIL` 回（初期値 10）間違えると `REDEEM_LOCK_MIN` 分間（初期値 5、最大 360）引き換えできない。パスワードは画面に置かず GAS で照合する |
| 在庫を超えた当選 | 当選時に「初期数 − 当選数」が残っている景品だけを割り当てる（ロック内） |
| 画面の改ざん | 当落は GAS が決め、画面には確率も景品構成も置かない |

※ ユーザーIDとスタンプ数は URL パラメータで受け取るだけなので、URL を書き換えれば偽装できます（許容すると決定済み）。本人確認やスタンプ数の正しさは保証されません。

## テストのやり直し

1. 抽選GASのスクリプト プロパティに `ALLOW_RESET` = `yes` を追加する。
2. 関数 `resetAllData` を実行する（Winners・Users・Logs の2行目以降を消去。`ALLOW_RESET` は自動で消える）。
3. アンケート回答は DROP_Lottery_Survey の Responses シートの2行目以降を手で消す。

参加者側のブラウザに残った画面間の状態は、タブを閉じれば消えます。

テストで LP を開くときは `?account_id=<UUID>&point=<スタンプ数>` を付けます。ユーザーIDは UUID 形式でないと通りません（例: `00000000-0000-4000-8000-000000000001` のように末尾を変えて使う）。

## 注意

- このリポジトリに秘密情報を置かないでください。引換パスワードは DB の Config シートにあります（v4.0-07 からスタッフ PIN・署名鍵は使いません）。
- GAS の同時実行は1スクリプトあたり約30件までです。本番前に同時に抽選するテストをしてください（`tools/loadtest/`。実行すると DB にデータが残るので、テスト環境で行い、終わったら `resetAllData` で消す）。
- 抽選・引換は ScriptLock 1本で順番に処理します。ロックを取れなかった要求（BUSY）は Logs に記録を試みます（同時に大量に来ると欠けるので最低限の件数として見る）。画面は自動で再試行します（合計30秒程度）。成功時の Logs の詳細にはロックの待ち時間・保持時間（`wait=…ms hold=…ms`）が入ります（上の「監視」）。
